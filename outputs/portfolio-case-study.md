# 企业 AI 工作台：项目案例说明

## 一句话介绍

企业 AI 工作台是一套面向制度、流程和项目交付资料的 AI 应用原型，支持知识库检索问答、引用依据、自然语言字段抽取、人工复核提示和执行轨迹展示。

## 为什么做这个项目

杭州五八同城 2026 年 11 月 2 日打开的一个 Python 开发岗位，职责包括第三方软件选型、API 集成、数据打通、AI 员工场景化训练、知识库建设、效果监控和跨团队沟通。这说明企业招聘关注的是 AI 应用能否接入业务并稳定运行，而不是只展示一个聊天页面。

因此，项目把“回答问题”扩展为一条可解释的交付流程：检索资料、生成回答、展示依据、识别是否需要人工复核，并把另一类常见任务做成结构化字段抽取。

## 当前功能

- 企业制度、请假流程和项目上线清单组成的演示知识库。
- 中文问题检索和相关文档排序。
- 回答展示来源文档和更新时间。
- 知识库没有足够依据时转人工复核。
- 从申请文本中提取金额、城市、事由和审核状态。
- 前端展示执行轨迹，便于演示、排错和交付。
- 默认演示模式，可切换 Ollama；保留 Dify blocking API 适配器。
- Node.js 原生 HTTP 服务，无第三方运行时依赖。
- 提供 FastAPI 适配层代码、Dockerfile 和 Docker Compose 启动配置，便于后续在有 Docker 的环境中复现部署。
- 提供 20 条离线评测集和自动评测脚本，覆盖问答、拒答、结构化抽取、工具调用、人工复核和故障回退。
- 文档导入支持 Markdown、纯文本和文件选择；对 PDF 返回明确的解析边界和错误提示，避免把未解析的二进制内容写入知识库。
- 文档导入接口具备标题、类型、内容长度、日期、文件类型和请求体大小校验，并返回可解释的 400/413 错误。

## 工程项目文档助手

为了把土木工程和 CAD 制图学习经历转化为场景理解能力，项目增加了工程文档助手。它处理项目技术交底、安全检查清单和合同验收条款，返回摘要、字段、依据、风险标记和人工复核状态。

这个场景不声称具备 CAD API 或工业软件二次开发能力。它展示的是跨行业 AI 落地能力：理解工程文档、搭建知识库、抽取项目字段、调用进度计算工具、识别安全和合同风险，并把高风险结论交给人工确认。

```text

```

## 可解释的技术决策

### 为什么默认使用演示回答器

作品集演示不能依赖面试现场的网络、API Key 或模型服务。默认模式可以稳定展示完整流程；连接 Ollama 或 Dify 后再替换模型回答层。模型调用失败时系统回退到演示回答器，并在执行轨迹里记录失败原因。

### 为什么必须显示引用依据

企业制度、费用和项目交付问题需要复核。系统不能只输出一段看起来流畅的话，而要告诉使用者回答来自哪些文档，并在找不到依据时明确转人工。

### 为什么保留执行轨迹

AI 实施岗位通常要处理部署、联调、测试和故障排查。执行轨迹可以让面试官看到系统做了哪些步骤，也能帮助定位问题是在检索、模型调用还是回退阶段发生的。

## 已完成验证

- Node.js 测试：9 个测试全部通过。
- 离线评测：20/20 条通过，报告写入 `docs/evaluation-report.json`。
- 本地页面：知识库问答页面能够运行。
- 服务级冒烟检查：`/api/health` 返回正常，知识库加载 6 份文档，工程审查接口可以返回 `human_review` 和风险标记。
- 问答：杭州出差住宿问题命中差旅制度，并显示引用依据。
- 无依据问题：能够返回人工复核提示。
- 流程抽取：能够从“出差地：杭州、费用：680 元”中提取字段，并判断需要人工复核。
- Ollama：使用本机 `qwen2.5:1.5b` 完成一次真实模型调用，未触发回退。
- 工程审查：临边防护隐患能够命中工程项目和安全检查文档，并返回 `human_review`。
- 工具调用：6/10 个工程节点返回 60% 完成率。
- Docker Compose：已提供静态配置，当前环境没有 Docker 命令，因此尚未在本机实际启动容器验证。
- 文档导入校验测试：覆盖 Markdown 输入、空内容、PDF 边界和支持类型说明。

## 面试演示顺序

1. 先问一个知识库中有依据的问题，展示引用。
2. 再问一个知识库中没有的问题，展示人工复核。
3. 打开流程抽取，展示自然语言到结构化字段的转换。
4. 点击检查服务，说明演示模式、Ollama 和 Dify 可以切换。
5. 解释一次模型服务失败时的回退和排错路径。
