# 动态技能进入规则

## 状态定义

| 状态 | 含义 | 课程动作 |
|---|---|---|
| 观察 | 证据太少或不够相关 | 记录，不安排课程 |
| 候选 | 证据达到初步门槛 | 放入下一次同步讨论 |
| 已批准 | 证据和学习成本都满足要求 | 安排一个动态课程槽位 |
| 固定核心 | 多岗位持续要求，属于共同能力 | 纳入固定课程 |
| 长期路线 | 重要但 8 周内不适合完成 | 不打断当前主线 |
| 暂缓 | 与目标不匹配或收益太低 | 暂不投入 |

## 证据权重

| 证据类型 | 权重 |
|---|---:|
| 详情已核实 | 1.0 |
| 搜索确认 | 0.5 |
| 企业招聘线索 | 0.3 |
| 岗位模型或跨城市参考 | 0.2 |
| 过期岗位 | 0.1 |

岗位相关性权重：A 档为 1.0，B 档为 0.7，C 档为 0.2。

## 进入动态课程的最低标准

满足全部条件：

- 至少 3 条独立岗位证据；
- 至少 2 条详情已核实；
- 至少 2 家不同公司；
- 至少 2 条 A/B 档岗位；
- 技能属于职责或明确要求，而不是页面关键词；
- 学习成本不超过 6–8 小时；
- 能在一节或两节课后留下可展示成果。

## 进入固定核心的标准

满足以下条件之一：

- 5 条以上详情已核实岗位持续要求；
- 至少 2 个城市、3 家公司反复要求；
- 至少占相关 A/B 岗位的 50%；
- 技能同时服务实施、开发和交付岗位。

## 长期路线标准

出现以下情况时，不进入 8 周主线：

- 预计学习时间超过 12 小时；
- 需要完整的新语言或新工程体系；
- 只服务于一个特殊岗位；
- 需要真实生产经验才能证明；
- 可能挤压 Python、API、RAG、部署和交付主线。

## 当前基线判断

当前 23 条岗位记录已经足以把以下内容视为固定核心：

- Python 和 API 集成；
- RAG、Agent 和 Workflow；
- 部署、日志和接口联调；
- 结构化输出、评测和人工复核；
- 需求梳理和企业交付。

当前不足以单独批准以下动态专项：

- LangChain、LangGraph、LlamaIndex 三者中的具体选择；
- Dify、Coze、FastGPT 的工具比较课；
- SQL/MySQL/Redis；
- RPA/n8n；
- TypeScript；
- C/C++。

这些技能保留在观察清单，等待更高质量岗位证据。
