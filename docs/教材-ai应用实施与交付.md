# AI 应用实施与 Agent 交付教材

版本：0.2

目标岗位：杭州优先、南京备选的 AI 应用实施、Agent 交付、FDE 初级、AI 解决方案助理、Python + AI 应用开发和 SaaS/RPA 实施岗位。

## 这套教材怎样保证学完不是“云里雾里”

课程不再按“读完多少章节”计算进度，而按能力目标验收。完整目标见 [学习目标与掌握清单](学习目标与掌握清单.md)。市场与课程的同步规则见 [双窗口同步机制](双窗口同步机制.md) 和 [动态技能进入规则](动态技能进入规则.md)。

整个 8 周分成 24 节核心课，每周 3 节。每节课最多引入 3 个新概念，概念按照依赖关系排列，绝不随机抽取。每节课只解决一个小问题，并把结果接到同一个企业 AI 工作台上。

你每节课会经历五步：

```text
先预测 → 只讲三个概念 → 跟做一个案例 → 做一个小变式 → 用自己的话复述
```

我在互动教学时不会一次把 24 节课的全部命令塞给你。教材保存完整路线，当前一轮只给你当前课的三个概念、当前案例和下一步操作。

## 每节课固定结构

每节课都使用同一张课卡：

```text
课次和主题
本节只学的三个概念
为什么这三个概念现在出现
案例目标
我先展示什么
你亲自操作什么
我检查什么
变式问题
通过标准
面试表达
```

这样做有两个好处：概念数量受控，学习结果有证据；操作不会变成机械复制命令。

## 8 周 24 节课程路线

### 第 1 周：先建立地图，再理解一次请求

本周案例：企业知识库助手的“差旅住宿问题”。

#### 第 1 课：岗位和项目到底解决什么问题

三个概念：AI 应用实施、输入/处理/输出、验收标准。

操作案例：阅读杭州富阳 Python/AI 软件集成岗位和杭州华途服务端 AI 全栈岗位，把“业务问题”写成一张需求卡。

你必须达到：能说清岗位不是单纯写代码，而是把业务问题变成可运行、可验证的系统。

证据：一张需求卡，包含输入、处理、输出、风险、验收。

#### 第 2 课：一次请求经过哪些组件

三个概念：客户端、服务端、接口。

操作案例：访问工作台首页和 `/api/health`，画出浏览器、Node 服务和响应之间的关系。

你必须达到：能回答“请求从哪里来、到哪里去、结果如何回来”。

证据：一张请求链路图和一段口头解释。

#### 第 3 课：为什么结果不能只有一段文字

三个概念：证据、状态、执行轨迹。

操作案例：调用 `/api/ask`，观察 `answer`、`evidence`、`needsHumanReview` 和 `trace`。

你必须达到：能解释企业 AI 为什么要展示依据、风险状态和执行过程。

证据：一份问答 JSON 和自己的字段解释。

### 第 2 周：用 Python 表达业务规则

本周案例：费用审批助手。

Python 的渐进学习范围见 [Python 学习路线](python学习路线.md)。本周只要求掌握业务代码中最常用的语法，不要求背完整 Python 语法表。

#### 第 4 课：Python 数据和 JSON

三个概念：变量、字典、列表。

操作案例：用 Python 表示一笔费用申请和多份知识库文档，打印成 JSON。

你必须达到：能看懂 Python 字典与 JSON 对象的对应关系。

证据：`expense_check.py` 的输入和输出。

#### 第 5 课：函数、条件和异常

三个概念：函数、条件判断、异常。

操作案例：判断 680 元是否超过 450 元标准，并处理负数或缺失金额。

你必须达到：能解释正常输入、错误输入和业务复核之间的区别。

证据：正常案例、错误案例和异常输出。

#### 第 6 课：文件和环境变量

三个概念：文件读取、环境变量、默认值。

操作案例：读取一份 Markdown 规则，并从环境变量读取模型名称；没有环境变量时使用默认值。

你必须达到：能解释为什么 API Key、模型地址和端口不能硬编码。

证据：一个文本读取脚本和一次环境变量结果。

### 第 3 周：理解和调用 API

本周案例：用接口完成文档导入、问答和费用计算。

#### 第 7 课：HTTP 请求的骨架

三个概念：GET/POST、请求体、响应体。

操作案例：分别调用 `/api/documents` 和 `/api/ask`，对照请求和响应。

你必须达到：能从接口文档中找到方法、路径、输入和输出。

#### 第 8 课：状态码和参数校验

三个概念：200/201、400、500。

操作案例：正常导入 Markdown、空标题导入、非法 JSON 请求，观察不同结果。

你必须达到：能根据状态码判断问题属于成功、输入错误还是服务异常。

#### 第 9 课：鉴权、超时和回退

三个概念：API Key、超时、回退。

操作案例：阅读 Dify/Ollama 配置，模拟错误模型地址，观察 `fallbackReason` 和 `trace`。

你必须达到：能说清模型失败后如何确认原因、如何保留证据、何时转人工。

### 第 4 周：RAG 和评测

本周案例：工程项目文档助手。

#### 第 10 课：文档、检索和上下文

三个概念：知识库文档、检索、上下文。

操作案例：导入工程验收 Markdown，提出一个有依据问题，查看命中的文档。

你必须达到：能说清 RAG 不是凭空回答，而是先找到资料再组织回答。

#### 第 11 课：引用、拒答和版本

三个概念：引用依据、依据不足、文档版本。

操作案例：分别测试有依据问题、无依据问题和旧版本文档问题。

你必须达到：能解释什么时候应该回答、什么时候应该拒答或转人工。

#### 第 12 课：评测集和失败案例

三个概念：评测问题、预期结果、失败原因。

操作案例：阅读 20 条评测集，挑出一条通过案例和一条失败案例，写出判断依据。

你必须达到：能设计一个可重复的测试，而不是只凭感觉说“效果不错”。

### 第 5 周：Agent、工作流和工具

本周案例：工程问题审查工作流。

#### 第 13 课：聊天、工作流和 Agent

三个概念：目标、步骤、工具。

操作案例：把“临边防护隐患”拆成识别、检索、风险输出和人工复核四步。

你必须达到：能区别普通问答和具有步骤、工具、校验的 Agent 工作流。

#### 第 14 课：结构化输出和工具调用

三个概念：字段、枚举状态、确定性工具。

操作案例：调用工程审查和进度计算接口，观察 `reviewStatus`、`riskFlags`、`percentage`。

你必须达到：能判断哪些结果应该由工具计算，哪些内容可以由模型组织。

#### 第 15 课：人工复核和可观察性

三个概念：风险升级、人工复核、trace。

操作案例：分别提交安全、合同付款和无依据问题，比较三种结果。

你必须达到：能解释为什么“模型说得很肯定”不等于“系统可以自动通过”。

### 第 6 周：FastAPI 和双接口能力

本周案例：把工程审查接口映射到 FastAPI。

#### 第 16 课：FastAPI 路由和请求模型

三个概念：路由、BaseModel、参数校验。

操作案例：阅读 `python_api/main.py`，找出 `/api/health`、请求模型和错误返回。

你必须达到：能不依赖逐行解释，说明一个 FastAPI 接口如何接收输入。

#### 第 17 课：Node 和 FastAPI 的接口一致性

三个概念：接口契约、字段一致、响应兼容。

操作案例：对照 Node 和 FastAPI 的 `/api/engineering/review`，列出路径、请求字段和响应字段。

你必须达到：能解释“换实现语言不能随意改变接口契约”。

#### 第 18 课：启动、联调和错误定位

三个概念：Uvicorn、端口、接口联调。

操作案例：启动 FastAPI，访问 `/api/health`，再调用工程审查接口并处理一个错误输入。

你必须达到：能启动服务、调用服务、根据错误判断下一步。

### 第 7 周：Linux、Docker、Ollama 和 Dify

本周案例：模型服务不可用时完成排错和恢复。

#### 第 19 课：进程、端口和日志

三个概念：进程、端口、日志。

操作案例：故意占用 3000 端口，改用 3001 启动，并记录错误到修复的过程。

你必须达到：能定位“服务没启动”和“端口被占用”的区别。

#### 第 20 课：环境变量和模型提供方

三个概念：配置、provider、健康检查。

操作案例：在 demo、Ollama 和 Dify 三种配置之间切换，观察 `/api/health`。

你必须达到：能说明应用、模型和外部服务之间的配置关系。

#### 第 21 课：Docker Compose 网络

三个概念：镜像、容器、服务名。

操作案例：阅读并在条件允许时启动 `docker-compose.yml`，解释为什么容器内访问 Ollama 要用 `http://ollama:11434`。

你必须达到：至少能按步骤启动、查看服务状态并解释网络结构。

### 第 8 周：交付、面试和迁移

本周案例：模拟客户交付一个工程文档助手。

#### 第 22 课：需求到验收

三个概念：POC、UAT、验收标准。

操作案例：把客户“希望 AI 帮我审查项目资料”写成需求、POC 和验收清单。

你必须达到：能把模糊需求变成可以测试和签收的目标。

#### 第 23 课：项目讲解和 Codex 边界

三个概念：项目价值、个人贡献、工具边界。

操作案例：完成 3 分钟项目演示，并回答“你到底做了什么”。

你必须达到：能说清 Codex 加速了什么，自己判断和验收了什么。

#### 第 24 课：岗位迁移和最终考核

三个概念：岗位匹配、技能证据、迁移回答。

操作案例：用同一个项目匹配杭州华途、富阳 Python/AI 软件集成和南京 AI 交付岗位。

你必须达到：能根据不同 JD 改写项目重点，并回答一个新业务场景。

## 每个案例怎样教得更人性化

### 先让你预测，再给答案

每个案例开始时，我先只告诉你业务目标和输入，让你预测系统应该做什么。你先形成自己的判断，再看实现。这样你是在学习解决问题，不是在复制命令。

### 先给最小成功路径，再加入一个错误

一个案例先只做“正常路径”。正常路径理解后，再加入一个错误，例如空字段、无依据、端口占用或模型地址错误。这样错误不会和新概念同时出现。

### 同一个案例只增加一个变化

费用助手先处理金额，再增加缺失金额，再增加人工复核。不会同时加入数据库、向量库、Docker 和多 Agent。

### 每节课都要有口头回忆

操作完成后，我会让你不用看代码回答一个问题，例如“为什么这里返回 human_review？”如果答不出来，说明只是操作完成，不能进入下一节。

### 每三节课设置一次小关卡

每周第三节课结束后，不再增加概念，而是做一个小变式。通过后才进入下一周；没通过时只补缺失的概念，不重学整周。

### 用岗位语言收尾

每节课最后都把能力翻译成面试表达，例如：

> 我能根据输入、依据和风险状态判断结果是否自动通过，并通过 trace 定位问题发生在哪一步。

## 课程进度记录方式

每节课记录四个状态：

```text
概念理解：未开始 / L1 / L2 / L3 / L4
案例操作：未开始 / 跟做完成 / 独立完成
错误解释：未完成 / 能定位 / 能修复
面试表达：未完成 / 能复述 / 能迁移
```

只有“概念理解达到目标、案例独立完成、错误至少能定位、面试表达能复述”才算本节通过。
