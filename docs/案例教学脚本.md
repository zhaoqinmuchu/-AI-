# 六个递进案例的教学脚本

案例不追求数量，而追求同一能力在不同场景中重复出现。每个案例都从最小成功路径开始，再加入一个错误或变化。

## 案例一：差旅费用助手

目标：建立输入、业务规则、结构化输出和人工复核的最初模型。

递进：

1. 输入 680 元和标准 450 元，得到超标结果；
2. 缺少金额，得到输入错误；
3. 增加城市、事由和审批状态；
4. 让你解释为什么金额判断交给规则而不是让模型猜。

## 案例二：企业文档问答

目标：理解 API、知识库、依据和无依据回答。

递进：

1. 查询已有制度；
2. 查看引用文档；
3. 查询知识库没有的内容并转人工；
4. 导入一份 Markdown 后再次提问。

## 案例三：工程项目文档助手

目标：把你的土木背景转化为工程文档理解能力。

递进：

1. 提取负责人和竣工日期；
2. 检索关键节点和验收条款；
3. 对设计变更问题提示审批；
4. 让你区分“文档依据”和“现场专业判断”。

## 案例四：工程安全审查 Agent

目标：理解 Agent/Workflow、风险升级、工具和人工复核。

递进：

1. 识别临边防护隐患；
2. 检索安全检查清单；
3. 返回 `human_review` 和风险标记；
4. 增加工程进度工具调用；
5. 让你画出执行轨迹。

## 案例五：模型和部署故障

目标：把“会做 Demo”提升为“能排错和交付”。

递进：

1. 正常启动服务；
2. 制造端口占用；
3. 制造错误模型地址；
4. 观察健康检查、日志、回退原因和最终复测。

## 案例六：客户交付和面试演示

目标：把技术能力迁移到岗位和客户语言。

递进：

1. 客户只说“希望 AI 帮我审查资料”；
2. 你提出澄清问题；
3. 写出 POC 和验收标准；
4. 演示系统；
5. 讲清个人贡献和后续迭代；
6. 把同一项目分别匹配 AI 实施、AI 全栈和 AI 交付岗位。

## 每个案例的教法顺序

### 第一步：业务故事

只给你一个真实工作场景，不先给技术名词。

### 第二步：预测结果

让你先说“系统应该收到什么、返回什么、什么情况不能自动通过”。

### 第三步：三个概念

只讲当前案例马上需要的三个概念。其他术语暂时只给一句话，不展开。

### 第四步：最小成功路径

先让正常输入跑通，确认你知道每一步的目的。

### 第五步：一个变化

只增加一个缺失字段、错误地址、无依据问题或风险条件。

### 第六步：脱离提示复述

让你用自己的话讲清输入、处理、输出、错误和验收。

### 第七步：岗位迁移

把案例改写成简历项目句子和面试回答。

## 我在互动中会怎样控制难度

- 你第一次遇到概念时，我给定义和最小例子；
- 第二次出现时，我只提醒关键词；
- 第三次出现时，我让你先判断，再给修正；
- 你连续两次能独立解释后，不再重复讲定义；
- 你操作成功但解释不清时，补一个“为什么”小练习；
- 你解释正确但操作失败时，补一个排错小练习；
- 你正常路径和错误路径都掌握后，才进入新案例。
